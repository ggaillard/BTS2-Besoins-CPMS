# Lexique

| Terme | Définition | Où on l'utilise |
|---|---|---|
| **ADR** | *Architecture Decision Record* : fiche courte qui trace une décision importante (contexte, options, décision, conséquences) | C6 · [étape 16](E16-dossier-solution.md) |
| **AIPD** | Analyse d'impact relative à la protection des données (*DPIA*) : étude obligatoire pour les traitements à risque élevé | S2 · [étape 13](E13-rgpd.md) |
| **AI Act** | Règlement européen sur l'intelligence artificielle ; son article 50 oblige à informer une personne qu'elle échange avec une IA | S2 · [étape 13](E13-rgpd.md) |
| **Artefact** | Document produit par la méthode (C1…S3) ; il vit dans le dépôt | partout |
| **Base légale** | Une des 6 raisons prévues par le RGPD qui autorisent un traitement (consentement, contrat, obligation légale, intérêt légitime, mission d'intérêt public, intérêts vitaux) | S2 |
| **Besoin exprimé** | Ce que le client dit vouloir, souvent sous forme de solution | [étape 1](E01-lire-le-besoin-exprime.md) |
| **Besoin réel** | Le problème que le client cherche à résoudre | C4 · [étape 7](E07-reformuler-le-besoin.md) |
| **Critère d'acceptation** | Condition observable qui permet de dire qu'un récit est satisfait | C4, M2 |
| **Criticité** | Probabilité × impact d'un risque | P2 |
| **DICP** | Disponibilité, Intégrité, Confidentialité, Preuve : les 4 besoins de sécurité d'une donnée | S1 · [étapes 6 et 10](E06-donnees-et-dicp.md) |
| **Donnée personnelle** | Information qui permet d'identifier une personne, directement ou non | S1, S2 |
| **Donnée sensible** | Catégorie particulière du RGPD (santé, opinions, religion, origine, orientation sexuelle, biométrie, génétique, syndicat) : traitement interdit sauf exception | S1, S2 |
| **ENF** | Exigence non fonctionnelle : *comment* la solution doit fonctionner (rapidité, accessibilité, sécurité, coût…) | C4 |
| **Gherkin** | Format `Étant donné… Quand… Alors…` pour écrire un critère d'acceptation testable | C4, M2 · [étape 8](E08-recits-gherkin-moscow.md) |
| **Go / No-go** | Décision de lancer (ou non) la mise en place, prise par le client au jalon J2 | C5 · [étape 15](E15-presenter-go-no-go.md) |
| **HDS** | Hébergeur de données de santé : certification obligatoire pour héberger des données de santé pour le compte d'un tiers | S2, C5 |
| **Indicateur d'usage / d'effet** | Usage : la solution est-elle utilisée ? Effet : le problème a-t-il diminué ? | M1 · [étape 9](E09-indicateurs.md) |
| **Jalon** | Point de contrôle où l'on vérifie qu'une phase est terminée (J0 à J4) | [METHODE](../METHODE.md) |
| **Minimisation** | Principe du RGPD : ne collecter que les données nécessaires à la finalité | S2 |
| **MoSCoW** | Priorisation : *Must, Should, Could, Won't (this time)* | C4 |
| **Partie prenante** | Toute personne ou organisation concernée par le projet ou par ses données | C1 · [étape 2](E02-parties-prenantes.md) |
| **PoC** | Preuve de concept : petite réalisation qui lève un doute précis | [étape 21](E21-preuve-de-concept.md) |
| **RACI** | *Responsible, Accountable, Consulted, Informed* : qui fait, qui valide, qui est consulté, qui est informé | P1 · [étape 17](E17-plan-projet-raci.md) |
| **Recette** | Vérification par le client que la solution fait ce qui était convenu | M2 · [étape 19](E19-recette.md) |
| **Récit utilisateur** | *En tant que… je veux… afin de…* : un besoin vu par un utilisateur | C4 |
| **Responsable de traitement / sous-traitant** | Celui qui décide pourquoi et comment on traite des données / celui qui les traite pour son compte (éditeur, hébergeur) | S2 |
| **Réversibilité** | Capacité à récupérer ses données et changer de solution | C4, S3 |
| **Règle 3-2-1** | 3 copies des données, sur 2 supports différents, dont 1 hors site | S3 |
| **SMART** | Spécifique, Mesurable, Atteignable, Réaliste, Temporel : qualités d'un bon indicateur | M1 |
| **TELOS** | Faisabilité Technique, Économique, Légale, Opérationnelle, calendaire (*Schedule*) | C5 · [étape 12](E12-faisabilite-telos-couts.md) |
| **Verbatim** | Phrase recopiée mot pour mot, entre guillemets | C3 · [étape 4](E04-mener-entretien-compte-rendu.md) |
